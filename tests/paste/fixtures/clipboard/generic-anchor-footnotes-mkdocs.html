Reproducible Builds

A build is reproducible when the same source, run through the same toolchain, yields a bit-for-bit identical artifact. The definition is easy; satisfying it is not, because compilers embed timestamps, paths, locale and thread-scheduling artefacts almost everywhere.1

The first class of nondeterminism is the easy one: recorded build time. Most toolchains now honour an environment variable that pins it, which turns a hard problem into a convention problem.2

The second class is filesystem ordering. Directory iteration order is not specified, so any build step that globs and concatenates is nondeterministic unless it sorts explicitly.3 This one accounts for a surprising share of real failures.

The third class — parallelism — is the genuinely hard one, and it is where most remaining irreproducibility lives.4

  2. SOURCE_DATE_EPOCH is now honoured by most major toolchains, though coverage is uneven. ↩

  3. Sorting at the point of glob expansion is the usual fix, and it is cheap. ↩

  4. Parallel builds can reorder output in ways that no amount of sorting will fix, because the nondeterminism is in the scheduler. ↩
