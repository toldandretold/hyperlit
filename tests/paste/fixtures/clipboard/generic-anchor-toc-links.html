1. Prerequisites

Before deploying anything you need credentials for the registry, a checked-out release branch, and a green build on that branch. The build must be green on the branch itself, not merely on a merge commit somewhere upstream of it.

2. Staging

Staging is a full copy of production with anonymised data. Deploying to it is a single command, and it should always be the first thing you do, even for changes you believe are trivial.

Back to top

3. Production

Production deploys are gated on a successful staging deploy plus a manual approval. The approval is a real gate and not a formality; the approver is expected to have looked at the diff.

Back to top

4. Rollback

Rollback is the same command with a previous release tag. It is fast, and you should reach for it early rather than trying to fix forward under time pressure.

  1. Identify the last known good tag.
  2. Run the deploy command against it.
  3. Confirm health checks pass.
  4. Write up what happened.
