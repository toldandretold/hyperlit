# Journal-Level Harvest (Diamond OA Registry)

The mission-level extension of the per-paper Source Network Harvester: instead of harvesting the sources *cited by* one book, harvest *every open-access work of one journal*, journal by journal, building toward hosting all diamond open-access research. Step-by-step operator guide: `app/Services/JournalHarvest/README.md`. Everything downstream of work selection is the existing harvest machinery — `AutoVersionCreator` → the `ContentFetchService` acquisition ladder → `listed=false` mint → `/maintainer/conversion` review — so a journal harvest is also a conversion-quality stress test for that journal's PDF style.

## The registry (`journal_sources`)

One row per journal (OpenAlex "source"): venue identity (`openalex_source_id` S-id, `issn_l`, `issns`), display metadata (`display_name`, `publisher`, `homepage_url`, `topics`, `languages`, `country_code`), the diamond determination (`is_diamond` + `diamond_provenance`), ranking stats (`works_count`, `cited_by_count`, `two_year_mean_citedness`), and harvest bookkeeping (`last_harvested_at`, `harvest_stats` jsonb, `shelf_id`). Each row also carries a `slug`, minted once and never rewritten — it is the journal's public page URL at `/j/{slug}` (the `j` segment is declared in `config/reserved-routes.php`).

Works link to their journal via `canonical_source.journal_source_id`, stamped at enumeration time. This — not the free-text `canonical_source.journal` string — is the join key: it makes journal-rooted eligibility an indexed SQL predicate (`HarvestEligibility::eligibleCanonicalsForJournal`) and will power the `/j/{slug}` works listing.

## Why DOAJ, not OpenAlex, decides "diamond"

Diamond = free to read AND free to publish (no APC). OpenAlex's `apc_usd` field cannot answer this: null means "unknown", not "free" — filtering `/sources` on `is_oa:true,is_in_doaj:true,apc_usd:0` matches only ~126 sources, while `apc_usd:null` matches ~17,900, and the pilot journal (Global Social Challenges Journal) itself carries `apc_usd: null`. DOAJ records an explicit has-APC flag for all ~23k of its journals (~14.6k are no-APC), so the rule in `DoajJournalDirectory::isDiamond` is: OpenAlex `apc_usd === 0` → diamond (`openalex_apc_0`); else DOAJ says no APC → diamond (`doaj_no_apc`); DOAJ says APC → not diamond; no DOAJ record → unknown, skipped by default (never claim diamond without evidence).

The full-registry sync reads DOAJ once via its CSV dump (`https://doaj.org/csv`, 307-redirects to signed S3); columns are read by header name and a missing APC column fails loudly rather than mis-parsing. The single-journal path uses the DOAJ API per ISSN. DOAJ's publisher/language fields also backfill journals where OpenAlex has nulls (common for small society journals).

## Commands

`php artisan journal:sync-registry --issn=2752-3349` — sync one journal by ISSN (the pilot path). Prints the diamond determination and the minted slug. Refuses to store a journal that is not provably diamond unless `--include-non-diamond`.

`php artisan journal:sync-registry` — full sync: OpenAlex `/sources` filtered `is_oa:true,is_in_doaj:true`, sorted most-cited-first, cross-checked against the DOAJ CSV. `--limit=500` keeps the most-cited N; `--topic=T10122` scopes to an OpenAlex topic; `--dry-run` counts without writing. Re-syncs refresh stats but never rewrite slugs.

`php artisan journal:list` — the worklist: registry ranked by `cited_by_count`, with works counts and `last_harvested_at`. `--all` includes non-diamond rows.

`php artisan journal:harvest <slug|S-id|ISSN> --max-works=25 --user=<admin username>` — the harvest itself, four inline stages: (1) enumerate all the journal's works via OpenAlex cursor paging (`primary_location.source.id` filter, `type:article` by default — `--type=` empty for all citable types), upsert them as canonicals via `CanonicalSourceMatcher::ingestExternal` (foundation_source `journal_harvest`) and stamp `journal_source_id`; (2) select eligible works most-cited-first (same predicate as the book-rooted harvester: no `auto_version_book`, OA, something fetchable); (3) per work, `AutoVersionCreator::create` — the whole existing ladder applies, JATS/HTML full text preferred (free) before PDF+OCR — with per-work try/catch so one bad PDF never kills the run; (4) add assigned books to the public `Journal: <name>` shelf (system creator) and merge run stats into the registry row.

`--dry-run` enumerates and reports eligibility without writing or fetching. `--skip-ocr` fetches without OCR. `--max-works` bounds the expensive stage — re-run to continue; every stage is idempotent, so Ctrl-C is always safe and a re-run resumes where it stopped. `--max-works=0` is enumerate/backfill only: it fills the console's article list for free, which is the cheapest way to make a journal actionable. Long runs on big journals: run under tmux/nohup; the sliced-queue-job pattern (as used by `SourceNetworkHarvestJob`) is the upgrade path if unattended runs are ever needed.

None of this is CLI-only any more: `⟳ enumerate` and `⇩ import` on `/maintainer/journal-import/{slug}` run the same stages through the same `JournalHarvestRunner`, so pick whichever fits — the CLI when you want the full per-work log and Ctrl-C, the console when you want to watch and review in one place. The stages themselves live in the runner precisely so the two can't drift; the command owns only option parsing, who-pays policy, and the coloured rendering of the runner's progress events.

## Billing and review

OCR is charged to the `--user` account after each successful import via `WorkOcrCharger` (the extracted, shared home of the set-BOTH-RLS-vars billing pattern — see its docblock; this half-copy has shipped broken twice). `assigned_existing` and failures are never charged; JATS/HTML lanes cost nothing. A run refuses to start OCR-charging work without `--user` (use `--skip-ocr`/`--dry-run` otherwise).

Imported books mint `visibility=public, listed=false` and flow through the standard review loop unchanged: `php artisan harvest:audit-imports --flag` to flag body-absent junk, review at `/maintainer/conversion`, approve to flip `listed=true` (`ReconvertQueue::promoteApprovedHarvest`) or retract (`HarvestRetraction`, which frees the canonical pointer for a re-harvest).

## Pilot recipe (GSCJ)

- `php artisan journal:sync-registry --issn=2752-3349` — expect S4387280908, diamond via `doaj_no_apc`, publisher Bristol University Press (DOAJ backfill), slug `global-social-challenges-journal`.
- `php artisan journal:harvest global-social-challenges-journal --dry-run` — ~107 works enumerated.
- `php artisan journal:harvest global-social-challenges-journal --max-works=5 --user=<you>` — small first batch; check conversions at `/maintainer/conversion` before going bigger.
- Re-run with larger `--max-works` until "journal fully harvested"; then `journal:list` for journal number two.

## The public journal pages (`/j`, `/j/{slug}`)

`/j/{slug}` is a homepage-class hero page (`journal-home.blade.php`, SPA pageType `journal`): lava lamp, hyperlit logo + journal name, about copy, and three shelf-backed feed buttons — Most Recent (`sort=published`: year → volume → issue desc, numeric-aware), Most Connected, Most Lit — driving the existing public shelf render endpoint against the journal's shelf, plus journal-scoped search via the public shelf search endpoint (`components/journal/journalSearch.ts`). No per-journal pseudo-books: a feed costs nothing until visited and rides the shelf machinery's lazy render + cache invalidation. `journal:sync-shelves` (and `journal:harvest` stage 4) reconciles shelf membership with the `canonical_source.journal_source_id` join and heals year/volume/issue onto version rows. Volume/issue flow OpenAlex → `canonical_source.volume/issue` → the minted library row; `journal:harvest --max-works=0` is enumerate/backfill-only. About copy auto-composes from DOAJ metadata (keywords, subjects, license, review process, ref URLs — synced by `journal:sync-registry`); `journal:set-about {slug} "..."` overrides it (`--clear` reverts). `/j` stays the static diamond index (native page load; `/j/{slug}` SPA-routes via the `journal` structure).

Commons artifacts (journal shelves, commons harvest shelves) live under the system creator, so migration `2026_08_12_000003` seeds a real `canonicalizer_v1` users row (unloggable: random password, not admin) — without it every `/u/canonicalizer_v1/shelf/…` link 404s, a latent bug in the commons harvest flow that the first journal shelf exposed. Locked by `tests/Feature/SourceHarvest/CommonsShelfUrlTest.php`; the pages by `tests/Feature/JournalRegistry/JournalPageTest.php`.

CSS gotcha: the hero card's styling is spread across `components/homepage.css`, `base/layout.css` (including the load-bearing `position: fixed` on `.fixed-header`) and `components/perimeterGlass.css`, all originally scoped `body[data-page="home"]` — every one of those selectors now also carries `body[data-page="journal"]`. A missed selector leaves the DOM perfectly valid while the card renders off-screen (the hero transform applies to a sticky element), which markup tests cannot see; `tests/e2e/specs/journal/journal-hero.spec.js` locks the RENDERED geometry (card in-viewport, centered, rounded, blurred, colon-to-title gap = one square width, feeds open, about copy reveals) — run with `npm run test:e2e` (manual, needs the GSCJ pilot in the registry; it skips otherwise).

The SPA grand tour predates the `journal` structure and does not cover it; `tests/e2e/specs/journal/journal-spa-navigation.spec.js` covers the journal's transitions instead: fresh load → feed card click into the reader (SPA-sentinel-verified, no reload), browser BACK into `/j/{slug}` (the popstate → journal rebuild), forward to the reader again, journal → user page (user button → My Library) → back → feed buttons still work, and the colon link home. That spec caught two real bugs on first run: `window.isOwner` leaking from the user page across SPA transitions and silently gating the journal feed buttons dead (fix: the journal shelf-branch is isOwner-blind + `initializeJournal` scrubs the global), and `DifferentTemplateTransition` pushing the URL only AFTER page init — on a cold cache that left seconds where the new page rendered under the old URL and Back could exit the site entirely (fix: URL pushes right after the body swap, before init; verified against the full grand tour). Known-by-architecture: hero-state links navigate NATIVELY (the SPA link interceptor is bound by lazyLoaderFactory, which exists only after a feed loads) — true on home too, so the colon-to-home step asserts a healthy landing, not an SPA transition. The e2e helpers (`getPageStructure`, `EXPECTED_COMPONENTS`) know the `journal` page type.

## Two lanes per work, and choosing between them

A work can carry two system versions at once: the vacuumed PDF (`foundation_source: canonical_pdf_vacuum`, `conversion_method: pdf_ocr_auto_raw`) and the publisher HTML (`journal_html` / `paste_engine_html`). They are sibling `library` rows on one canonical, each with its own book id and `resources/markdown/{book}/` — the same shape the ar5iv lane has used since it existed, so nothing in the versions model changes. `HtmlLaneCreator` mints and imports the HTML one; it deliberately bypasses `AutoVersionCreator`, which is hard-wired to the PDF foundation and short-circuits at `assigned_existing` the moment any lane has content.

HTML acquisition is a two-rung ladder (`ContentFetchService::importHtmlPage`): a **plain proxied GET first**, the Playwright browser (`scripts/fetch-html.mjs`) only when the plain page fails a gate. The browser used to be the only channel on the assumption it was the safer one; Bristol UP (Atypon) proved the opposite (2026-08-17) — it serves the complete server-rendered article to a bare GET through the same proxy pool while intermittently handing the headless browser an HTTP-200 shell with zero prose, which the body gate then rejected three GSCJ articles in a row. Both rungs pass the same wall/identity/body gates, so a JS-challenge page fetched plainly is condemned there and falls through to the browser; `fetch_trace.json` records which rung won as `html_channel`. A body-absent rejection now also writes the condemned page to `resources/markdown/{book}/rejected_page.html` (cleared by a later success) — without it a soft bot-block and a genuine abstract-only landing page are indistinguishable after the fact. Gates: `tests/Canonical/AcquisitionGateTest.php` ("channel ladder" section).

Exactly one lane is **the version**: `canonical_source.auto_version_book` names it, only it is `listed`, and it's what `/j/{slug}`, the shelf and readers resolve to. The other stays imported but unlisted for comparison. Left alone the winner is whichever lane was created FIRST (`AutoVersionResolver` orders by `created_at`) — arbitrary and invisible, which is why `JournalVersionPromoter` exists. Promotion moves the pointer, flips the listing, and **swaps shelf membership**: `HarvestShelf::syncJournalShelfMembership` is additive, so without that last step the journal's feeds keep serving the lane you just demoted.

Import HTML with `journal:harvest <slug> --lane=html|both` (free — only PDF runs OCR), compare at `/maintainer/journal-import/{slug}`, promote with the ★ button or `journal:promote-version <book>`. `--force-html` re-converts lanes that already have content — the path a publisher-processor fix travels to reach already-imported articles — and re-promotes afterwards, because `persistArticle` rewrites the row with `listed = false` and would otherwise pull the promoted lane out of the journal's feeds.

The reader in the left pane is the REAL reader, framed. Session history is joint across a browsing context, so its normal container-close (`history.back()`, consuming the entry the open pushed) steps whatever entry is last in the WHOLE context — which here is another frame's navigation. Live symptom: closing a citation blanked the reader pane (`about:blank`), or the source pane's PDF, or navigated the console itself ("the whole page gets cooked"). `resources/js/utilities/embeddedReader.ts` gates every container history write on "am I framed": embedded, the container closes in place and records state with `replaceState` only — no pushState on open, no back() on close, so the host's history is never touched. At top level every guard is a no-op, so reader behaviour is unchanged (open still pushes `?cs=1`, Back still unwinds a level). GOTCHA if you are ever tempted to stop the frames adding joint-history entries by navigating them with `location.replace()` instead of `.src`: don't. A replace() issued from the frame's own `about:blank` document is treated as a third-party initiator by WebKit, so the `SameSite=Lax` session cookie is not sent and both panes come back `{"message":"Unauthenticated."}` — measured, `.src` keeps the session and `location.replace()` loses it on the identical URL. The extra history entries are the lesser evil; recreating the iframe ELEMENT per selection is the route that would avoid both.

The console starts a journal, not just fixes one. Two JOURNAL-scoped buttons sit in the detail header beside the per-article ones: **⟳ enumerate** (ask OpenAlex what this journal has published and upsert those works as canonicals — free, no publisher contacted, no OCR) and **⇩ import** with a lane picker (HTML / PDF / both) and a cap (next 5 / 25 / 100 / all eligible). Enumerate is load-bearing rather than convenient: the article list IS `canonical_source WHERE journal_source_id = <journal>`, and every other control on the page targets an article row, so before it runs the page is empty AND unactionable — which is exactly how it read to an operator who had only ever run `journal:sync-registry`. HTML is the default lane because it is free and, on the pilot journal, converted better than OCR; PDF spends money, so a bulk import confirms before firing, and "all eligible" confirms even on the free lane (it still hammers one publisher). Both actions run the SAME `JournalHarvestRunner` stages `journal:harvest` runs — the console is a second face on one implementation, not a second implementation.

A journal-scoped run may touch any work of the journal, so it excludes and is excluded by everything else on that journal in BOTH directions (a sweep and a per-article import racing on one work would interleave node writes); a different journal is unaffected. Because `$timeout` must stay under the queue's `retry_after` — otherwise a long job is re-dispatched while the first copy is still writing — a bulk run stops itself at a time budget and reports "press again to continue" rather than being killed mid-article; every stage is idempotent and works are taken most-cited-first, so the next press resumes instead of repeating. `import_all` bills the admin who pressed it, per successful new import only, exactly as the CLI bills `--user`.

The console acts as well as compares. Per lane: **↻ reconvert** (re-run the converter over the page already on disk — no network, no cost, input held constant so the only variable is your processor fix), **⇩ re-fetch** (go back to the publisher, for when what we stored isn't the article), and the two bundles **⤓ conversion** / **⤓ harvest** — the same converter-vs-acquisition fork, which is why neither is a default. An article with no lanes offers **PDF / HTML / both**. All of it queues a `JournalImportActionJob` on `citation-pipeline` against a `journal_import_runs` row the page polls (these actions fetch, OCR and cost money, so none runs in the request); the poll carries a 30-minute stale-run watchdog, and a second run on the same target joins the first rather than interleaving node writes with it. The PDF lane's reconvert is deliberately the shared `/maintainer/conversion` one — one reconvert implementation, not two — and re-acquiring a PDF stays a retract-and-re-harvest.

The source pane is SANDBOXED (`sandbox="allow-same-origin"`, no `allow-scripts`). The fetched publisher page is served from our own origin, so its JavaScript would otherwise run same-origin with the admin console — the session cookie is HttpOnly, but same-origin `fetch('/api/…')` doesn't need to read it, the browser attaches it. Demonstrated with a planted hostile page: unsandboxed its script ran, read the parent DOM, and got HTTP 200 from `/api/maintainer/conversion/flags` as the logged-in admin; sandboxed the browser blocks execution outright. `allow-same-origin` WITHOUT `allow-scripts` is the exact pair required — it stops execution while keeping the origin, so the theme injection still reaches the document; a bare `sandbox=""` would give it an opaque origin and silently break the theming, and adding `allow-scripts` would let the frame remove its own sandbox. PDFs are left unsandboxed for the browser's viewer. Which of the two a source is comes from the response's **Content-Type**, not the artifact list: a book opened by deep link (`?book=`) isn't in the flag queue and arrives with `artifacts: []`, which read as "PDF/binary" and silently dropped the sandbox — that was a real hole, and the header can't be missing. Gate: `tests/javascript/architecture/maintainerSourceSandbox.test.js`.

The source pane renders in the operator's theme: the fetched page is same-origin, so `utilities/sourceFrameTheme.ts` injects a stylesheet built from the live theme custom properties (read off `<body>`, where the `theme-*` class lives — off `documentElement` you get the dark defaults and every theme looks dark). PDFs are excluded by ARTIFACT, not by inspecting the document — WebKit gives its PDF viewer a real `body`, so a body check reports a PDF as skinnable — and fall back to a light canvas the viewer overpaints. Shared with `/maintainer/conversion`; `tests/javascript/utilities/sourceFrameTheme.test.js` locks the artifact rule.

Each lane also carries the conversion page's detail strip — book id (click to copy), `open ↗`, and a **note** that is stored on the book's open flags and rides the case bundle into dev. Noting a lane nobody has flagged opens a `manual` flag to hold it: you spotting the bad conversion IS the report, and a note with nowhere to live never reaches the bundle. **✓ fixed / ✕ dismiss** close the case on the same page, via a journal-import-specific endpoint rather than the shared conversion resolve — that one lists whatever it approves (approval is the listing gate when a flagged book is the only version of its work), which on a losing lane would publish a second version of one article; here listing follows only for the already-promoted lane. The bundle manifest gained `origin` (which console exported it), a `lane` block (foundation_source, conversion_method, promoted-or-not, and every sibling lane with the same facts) and a `journal` block (slug, name, publisher, ISSN-L, console URL) — because for a harvest case off a journal, WHICH lane broke and whether the sibling is fine is the diagnosis, and `canonical_source.json` alone leaves the importing side holding an unresolvable `journal_source_id`. The `journal_sources` row travels in `db/` and imports insert-if-absent, so the pulled case opens in a local journal-import console.

## Investigating a run's failures

"13 failed" is not a diagnosis, and neither is a list of 13 titles: the question is whether they are empty shells (publisher intermittency — press the button again) or identity/converter failures (ours to fix), and the counts per CAUSE are what answer it. So a bulk run now records each failed work on its `journal_import_runs` row (`counts.failures`: lane, title, canonical id, book, status, reason, capped at 100), and the console renders them grouped by reason, biggest cause first, with a **copy** button that reproduces the same grouping as plain text. Each row clicks straight through to that article. A **failed only** filter sits beside "imported only" — a failed import still mints its lane row, so "failed" means a lane with no content.

Per ARTICLE the evidence already existed and is worth knowing about before building anything new: `library.pdf_url_status` holds the failure reason (the console shows it as the "no content" badge and in the converted pane), `resources/markdown/{book}/fetch_trace.json` records won host, channel, body verdict/reason, proxy session, `ip_retry` and images stored/failed, and `rejected_page.html` keeps the condemned page itself — the only way to tell a soft bot-block from a genuine abstract-only landing page after the fact. The **⤓ harvest** bundle ships the canonical row plus that trace for one article.

The page that killed the converter is now kept too (`rejected_page.html`, the same slot a body-absent page uses). Previously `fetched_page.html` was written only on success and `rejected_page.html` only on a body verdict, so an engine CRASH — the one case where the input is most worth having — discarded it, and a big-page failure could only be guessed at: diagnosing the 1,719KB abort meant synthesising a page of roughly the right size, which did not reproduce it.

A failure reason has to carry its own diagnosis, because the run that produced it is long gone by the time you read it. The paste engine is the case that proved it: a signalled Node process reported "the process has been signaled with signal" and nothing more, because the message was truncated at 120 characters — cutting off the signal NUMBER, which is the entire diagnosis (9 = the kernel's OOM killer, 6 = Node's own heap limit, 11 = a crash in the parser). `pdf_url_status` is a `text` column, so the truncation bought nothing at all. `runPasteEngine` is now the single place both lanes call, and it names the signal, the page size (this failure scales with page size, so it clusters on a journal's biggest articles rather than being random) and, on a non-signal failure, the exit code plus whatever Node put on stderr.

## A blocky TITLE alone is not a wall

The last GSCJ failure was ours, not the publisher's. `AccessWallDetector`'s second stage checks the page `<title>` against `GarbageDetector::isBlockPhrase`, whose vocabulary includes `results for` (next to `search results`) — and the article was titled "Can organizational frameworks drive institutional change and **results for** gender equality?". It was condemned as an interstitial while the stored page carried 627KB and ~88,000 characters of the actual paper. The class already knew this string was dangerous: section headings were explicitly exempted because "a genuine article can be headed 'Results for the primary endpoint'". Titles simply never got the same exemption.

A block-phrase title now has to be CORROBORATED by an empty-looking page (under ~2,000 characters of visible text, matching `GarbageDetector::MIN_TOTAL_CHARS`). A challenge page is a few hundred characters of "prove you are human"; a paper is tens of thousands. Fixing it this way rather than by editing the vocabulary keeps the phrase working for its other consumers (`WebArticleVerifier`, `library:flag-sweep`, the post-import node scan), where it is applied to different text under different rules. Both directions are locked: `tests/Canonical/AcquisitionGateTest.php` asserts the real article passes AND that the same title on an empty page is still caught.

Diagnostic note: this one presented confusingly because the panel's reason and the row's `pdf_url_status` disagreed — the panel showed the FIRST verdict (the bogus interstitial) while the row held the LAST one written (a genuine WAF challenge on the retry IP). `retryOnFreshSession` returns the first result when both attempts are retryable, so when those two disagree, suspect that the first verdict is the one describing what actually happened to the content.

## Bristol's wall is AWS WAF, and it says so in a header

The 2026-08 GSCJ batch's "no article body — 0 prose / 0 chars" failures were not thin pages and not publisher flakiness: `bristoluniversitypressdigital.com` sits behind CloudFront + AWS WAF Bot Control, which answers a challenged request with **405 and `x-amzn-waf-action: captcha`**. Two things followed from that, both of which sent the diagnosis the wrong way. `AccessWallDetector` had markers for PerimeterX, Cloudflare, reCAPTCHA/hCaptcha, Imperva and Akamai but not AWS WAF, so the rendered puzzle wasn't recognised as a wall; and `fetchHtmlPlain` discarded the 405 as a nondescript null, so we escalated to Playwright, which renders the puzzle as a perfectly ordinary HTTP 200 — zero prose — and the body gate filed it as "publisher landing page or abstract only". Every one of these failures carried `html_channel: browser` for exactly that reason.

Both halves are now fixed: `awswaf.com` is a marker (the HOST, because the visible prose is localised — the captured page carried Arabic — and the token path segments are per-request), and the plain rung believes the header, failing immediately as `access_wall` instead of spending 70s rendering a CAPTCHA. Note the URL shape while debugging: WAF intercepts at `/view/journals/…`, so a trace showing that un-prefixed path (rather than the `/gsc/view/…` the 301 leads to) means the redirect never happened because the challenge came first.

What this does NOT fix is getting in. The challenge is scored on the address: the residential proxy pool is challenged and so is the droplet's own datacentre IP, so the fresh-IP retry is honest bookkeeping rather than a way through. Given 36 works imported before the challenges began, a rate-based rule is the likeliest trigger — which makes pacing the lever worth reaching for before proxy shopping. All three pacing knobs are therefore config, not constants, because the right value is a property of the PUBLISHER's rules and can only be found by experiment: `HARVEST_WORK_SLEEP` (seconds between works, default 2 — also the CLI's `--sleep` default, so the console and the command cannot disagree), `HARVEST_IMAGE_DELAY_MS` (milliseconds between an article's image downloads, default 400 — load-bearing alongside the first, since a figure-heavy article otherwise fires a dozen requests at one host inside a single inter-work gap), and `HARVEST_RETRY_DELAY` (seconds before the one fresh-IP retry, default 3). All cost only wall-clock; raise them when a publisher starts challenging mid-run.

## The empty-shell retry

Atypon does not 403 a harvester, it intermittently hands back an HTTP-200 page with zero prose — the 2026-08-17 GSCJ batch lost about one work in five to it, while a bare GET from a clean IP returned the full article seconds later. Diagnosis note for next time: the giveaway in the log is the URL. Bristol 301s `/view/journals/…` to `/gsc/view/journals/…`, so a trace that records the UN-prefixed URL means the server answered 200-with-shell instead of redirecting — a redirect cannot leave a client stranded mid-chain. Both fetch channels inherit the work's single sticky-proxy session, so one unlucky IP wrote the work off entirely.

`importHtmlLane` now retries ONCE on a fresh session (= a fresh residential IP) for the failures that are verdicts on the ASKER rather than on the work. Every failure carries a `gate` naming what refused it, and `RETRYABLE_GATES` is the list worth a second address: `body_absent` (an empty shell), `access_wall` (a bot check) and `fetch_failed`. Two are deliberately excluded — `engine_crash` is deterministic on page size, so a second IP fetches identical bytes and dies identically, and a rejected IDENTITY means the page is not the article, which it will not be from anywhere else either. One retry, not a loop: a genuinely walled or abstract-only page must still fail fast rather than tripling the load on a publisher we want to stay welcome at. Skipped entirely when no proxy is configured, since that "retry" is this machine asking the same question from the same address. Locked by three tests in `tests/Canonical/AcquisitionGateTest.php` (second IP wins, shell-from-both-fails-at-two-attempts, no-proxy-no-retry).

Two testing gotchas that cost real time here. `Http::fake` cannot reach into the browser rung's Node subprocess, so an unstubbed Playwright channel turns a gate test into a multi-minute hang on its 70s process timeout — hence `services.source_fetch.browser` (`SOURCE_FETCH_BROWSER`, default true), which is honest anyway since Playwright is an optional host capability. And `UrlGuard` resolves DNS, so an image-heavy fixture costs a lookup per image: the harvester now memoises the verdict per HOST for the life of one harvest (an article's figures are nearly always one host), and these tests use a synthetic image-free article rather than a real fixture.

## Figures: acquired, not hotlinked

The HTML lane used to keep whatever `src` the publisher's markup carried, which produced the same broken-image placeholder for two opposite reasons. A ROOT-RELATIVE src (Bristol UP serves `/gsc/view/journals/gscj/2/1/…f001.jpg`) was stored verbatim, so the reader resolved it against OUR origin — `hyperlit.io/gsc/…` — and 404'd every time; that one was never about hotlink blocking, the URL simply pointed nowhere. An ABSOLUTE src (OUP's silverchair CDN) did point somewhere real but hotlinked it, so a book we host loses its figures the day the publisher blocks the referer or rotates the path. `ArticleImageHarvester` now downloads every `<img>` at import time, stores it through the existing `BookImageStore` seam (the same private disk + `book_images` rows the PDF/EPUB paths use) and rewrites the src to `/{book}/media/{file}` — the figures are acquired exactly like the text is, which for a CC-BY diamond article they are entitled to be.

The download itself stays in `ContentFetchService`, because publisher image endpoints care about the session, proxy IP and **Referer** that fetched the page — a bare GET of the identical URL often 403s where the article's own request succeeds, which is the "they're blocking it" symptom. Related and load-bearing: the base URL for resolving relative srcs is now where the fetch actually LANDED, not what we asked for. We are nearly always handed a DOI, and doi.org redirects to the publisher, so resolving `/gsc/view/…` against the requested URL would point every figure at doi.org; both HTML channels now report their final URL (`fetch-html.mjs` already returned `finalUrl` — it was being discarded) and it is recorded on the fetch trace as `page_url` so a RECONVERT, which has no network, can resolve them too.

The `src` attribute is often NOT where the figure is. Atypon (Bristol UP, OUP) lazy-loads: it ships `<img src="/skin/…/img/Blank.svg" data-image-src="/gsc/view/…/f001.jpg">` and swaps the real path in with JavaScript, so reading `src` downloads a blank placeholder and stores it AS the figure — which is worse than the original bug, because a blank image looks like it worked. The same article's tables carry a real `src` and no data-attribute, which is exactly why some figures came back fine and others came back empty from one page. So candidates are tried lazy-attributes-first (`data-image-src`, `data-original`, `data-lazy-src`, `data-full-src`, `data-hires`, `data-src`, `data-srcset`) before `src` and `srcset`, and the winning attribute set is stripped afterwards so nothing downstream can follow them home. The lazy attribute beats the placeholder-name heuristic deliberately: a page that carries `data-image-src` is telling us where the image is, whereas a name check only catches placeholders that happen to be called `Blank.svg`.

Guards worth keeping: a candidate whose filename reads as a placeholder (blank/spacer/pixel/transparent…) loses to any real one and a decoded image of 2x2 or smaller is refused outright (both belt-and-braces for the lazy-load case above), srcset/data-srcset are stripped (they out-rank the rewritten src and would send the reader straight back to the publisher), bytes are decoded before storing (a hotlink-blocking publisher answers 200 with an HTML "access denied" page, which would otherwise be stored as `figure1.jpg`), filenames are hash-prefixed (one article carries the same basename from different directories — Bristol emits an `inline-` and a `full-` variant of one figure), ingest prunes (each lane owns its own book id, so a re-import after a processor fix must not orphan the previous run's figures), and every URL passes `UrlGuard::isSafeFetchUrl` **at discovery**, not just at fetch — these srcs come out of a third-party page, so an `<img src="http://169.254.169.254/…">` is a live SSRF vector. A figure that cannot be fetched is left ABSOLUTE rather than relative (it at least stands a chance) and never fails the import. Downloads are also SPACED (400ms between them, between-only so a one-figure article pays nothing): the sweep's 2s inter-article pause was set when an article was a single request, and a figure-heavy page otherwise fires a dozen image requests inside that gap — the burst a publisher actually notices. Locked by `tests/Feature/SourceHarvest/ArticleImageHarvesterTest.php`, which injects the fetcher so there is no HTTP in the suite.

GOTCHA for any future re-import path: they all end in `persistArticle`, which rewrites the row with `listed = false`. On the promoted lane that silently drops the article out of `/j` and the shelf, so the job and `--force-html` both re-promote afterwards (found live, locked by `JournalLaneTest`).

Two gotchas the GSCJ pilot surfaced, both invisible to markup-level tests. **Publisher front matter can live OUTSIDE the article container**: on Bristol UP the title, authors, affiliation, abstract and keywords sit in a metadata card ABOVE `#articleBody`, so scoping to the body (the right move for the furniture) silently dropped all of them and the book opened cold on "Key messages" — `BristolUPProcessor::buildArticleHeader` rebuilds them, taking the abstract once because the platform emits the block twice as responsive duplicates. **A percentage-height pane needs a definite height all the way to the root**: `body.ji-detail html` is a descendant selector that can never match (the root element is not inside `<body>`), so `<html>` never got its height, `.ji-columns { height: calc(100% - 45px) }` resolved to `auto`, and the three panes grew to the full 107-article list (~8300px). The reader and the HTML source pane still looked right — they flow from the top — but Safari's PDF viewer fits its page to the frame and centres it, so the visible top of an 8340px-tall frame was pure grey backdrop, which reads exactly like "the PDF failed to load". The gate is `tests/javascript/architecture/cssStructure.test.js` ("no descendant selector ending in html/:root").
