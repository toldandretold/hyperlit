# Journal-Level Harvest (Diamond OA Registry)

The mission-level extension of the per-paper Source Network Harvester: instead of harvesting the sources *cited by* one book, harvest *every open-access work of one journal*, journal by journal, building toward hosting all diamond open-access research. Step-by-step operator guide: `app/Services/JournalHarvest/README.md`. Everything downstream of work selection is the existing harvest machinery — `AutoVersionCreator` → the `ContentFetchService` acquisition ladder → `listed=false` mint → `/maintainer/conversion` review — so a journal harvest is also a conversion-quality stress test for that journal's PDF style.

## The registry (`journal_sources`)

One row per journal (OpenAlex "source"): venue identity (`openalex_source_id` S-id, `issn_l`, `issns`), display metadata (`display_name`, `publisher`, `homepage_url`, `topics`, `languages`, `country_code`), the diamond determination (`is_diamond` + `diamond_provenance`), ranking stats (`works_count`, `cited_by_count`, `two_year_mean_citedness`), and harvest bookkeeping (`last_harvested_at`, `harvest_stats` jsonb, `shelf_id`). Each row also carries a `slug`, minted once and never rewritten — it is the journal's public page URL at `/j/{slug}` (the `j` segment is declared in `config/reserved-routes.php`).

Works link to their journal via `canonical_source.journal_source_id`, stamped at enumeration time. This — not the free-text `canonical_source.journal` string — is the join key: it makes journal-rooted eligibility an indexed SQL predicate (`HarvestEligibility::eligibleCanonicalsForJournal`) and will power the `/j/{slug}` works listing.

## Why DOAJ, not OpenAlex, decides "diamond"

Diamond = free to read AND free to publish (no APC). OpenAlex's `apc_usd` field cannot answer this: null means "unknown", not "free" — filtering `/sources` on `is_oa:true,is_in_doaj:true,apc_usd:0` matches only ~126 sources, while `apc_usd:null` matches ~17,900, and the pilot journal (Global Social Challenges Journal) itself carries `apc_usd: null`. DOAJ records an explicit has-APC flag for all ~23k of its journals (~14.6k are no-APC), so the rule in `DoajJournalDirectory::isDiamond` is: OpenAlex `apc_usd === 0` → diamond (`openalex_apc_0`); else DOAJ says no APC → diamond (`doaj_no_apc`); DOAJ says APC → not diamond; no DOAJ record → unknown, skipped by default (never claim diamond without evidence).

The full-registry sync reads DOAJ once via its CSV dump (`https://doaj.org/csv`, 307-redirects to signed S3); columns are read by header name and a missing APC column fails loudly rather than mis-parsing. The single-journal path uses the DOAJ API per ISSN. DOAJ's publisher/language fields also backfill journals where OpenAlex has nulls (common for small society journals).

## Commands

`php artisan journal:sync-registry --issn=2752-3349` — sync one journal by ISSN (the pilot path). Prints the diamond determination and the minted slug. Refuses to store a journal that is not provably diamond unless `--include-non-diamond`.

`php artisan journal:sync-registry` — full sync: OpenAlex `/sources` filtered `is_oa:true,is_in_doaj:true`, sorted most-cited-first, cross-checked against the DOAJ CSV. `--limit=500` keeps the most-cited N; `--topic=T10122` scopes to an OpenAlex topic; `--dry-run` counts without writing. Re-syncs refresh stats but never rewrite slugs.

`php artisan journal:list` — the worklist: registry ranked by `cited_by_count`, with works counts and `last_harvested_at`. `--all` includes non-diamond rows.

`php artisan journal:harvest <slug|S-id|ISSN> --max-works=25 --user=<admin username>` — the harvest itself, four inline stages: (1) enumerate all the journal's works via OpenAlex cursor paging (`primary_location.source.id` filter, `type:article` by default — `--type=` empty for all citable types), upsert them as canonicals via `CanonicalSourceMatcher::ingestExternal` (foundation_source `journal_harvest`) and stamp `journal_source_id`; (2) select eligible works most-cited-first (same predicate as the book-rooted harvester: no `auto_version_book`, OA, something fetchable); (3) per work, `AutoVersionCreator::create` — the whole existing ladder applies, JATS/HTML full text preferred (free) before PDF+OCR — with per-work try/catch so one bad PDF never kills the run; (4) add assigned books to the public `Journal: <name>` shelf (system creator) and merge run stats into the registry row.

`--dry-run` enumerates and reports eligibility without writing or fetching. `--skip-ocr` fetches without OCR. `--max-works` bounds the expensive stage — re-run to continue; every stage is idempotent, so Ctrl-C is always safe and a re-run resumes where it stopped. Long runs on big journals: run under tmux/nohup; the sliced-queue-job pattern (as used by `SourceNetworkHarvestJob`) is the upgrade path if unattended runs are ever needed.

## Billing and review

OCR is charged to the `--user` account after each successful import via `WorkOcrCharger` (the extracted, shared home of the set-BOTH-RLS-vars billing pattern — see its docblock; this half-copy has shipped broken twice). `assigned_existing` and failures are never charged; JATS/HTML lanes cost nothing. A run refuses to start OCR-charging work without `--user` (use `--skip-ocr`/`--dry-run` otherwise).

Imported books mint `visibility=public, listed=false` and flow through the standard review loop unchanged: `php artisan harvest:audit-imports --flag` to flag body-absent junk, review at `/maintainer/conversion`, approve to flip `listed=true` (`ReconvertQueue::promoteApprovedHarvest`) or retract (`HarvestRetraction`, which frees the canonical pointer for a re-harvest).

## Pilot recipe (GSCJ)

- `php artisan journal:sync-registry --issn=2752-3349` — expect S4387280908, diamond via `doaj_no_apc`, publisher Bristol University Press (DOAJ backfill), slug `global-social-challenges-journal`.
- `php artisan journal:harvest global-social-challenges-journal --dry-run` — ~107 works enumerated.
- `php artisan journal:harvest global-social-challenges-journal --max-works=5 --user=<you>` — small first batch; check conversions at `/maintainer/conversion` before going bigger.
- Re-run with larger `--max-works` until "journal fully harvested"; then `journal:list` for journal number two.

## The public journal pages (`/j`, `/j/{slug}`)

`/j/{slug}` is a homepage-class hero page (`journal-home.blade.php`, SPA pageType `journal`): lava lamp, hyperlit logo + journal name, about copy, and three shelf-backed feed buttons — Most Recent (`sort=published`: year → volume → issue desc, numeric-aware), Most Connected, Most Lit — driving the existing public shelf render endpoint against the journal's shelf, plus journal-scoped search via the public shelf search endpoint (`components/journal/journalSearch.ts`). No per-journal pseudo-books: a feed costs nothing until visited and rides the shelf machinery's lazy render + cache invalidation. `journal:sync-shelves` (and `journal:harvest` stage 4) reconciles shelf membership with the `canonical_source.journal_source_id` join and heals year/volume/issue onto version rows. Volume/issue flow OpenAlex → `canonical_source.volume/issue` → the minted library row; `journal:harvest --max-works=0` is enumerate/backfill-only. About copy auto-composes from DOAJ metadata (keywords, subjects, license, review process, ref URLs — synced by `journal:sync-registry`); `journal:set-about {slug} "..."` overrides it (`--clear` reverts). `/j` stays the static diamond index (native page load; `/j/{slug}` SPA-routes via the `journal` structure).

Commons artifacts (journal shelves, commons harvest shelves) live under the system creator, so migration `2026_08_12_000003` seeds a real `canonicalizer_v1` users row (unloggable: random password, not admin) — without it every `/u/canonicalizer_v1/shelf/…` link 404s, a latent bug in the commons harvest flow that the first journal shelf exposed. Locked by `tests/Feature/SourceHarvest/CommonsShelfUrlTest.php`; the pages by `tests/Feature/JournalRegistry/JournalPageTest.php`.

CSS gotcha: the hero card's styling is spread across `components/homepage.css`, `base/layout.css` (including the load-bearing `position: fixed` on `.fixed-header`) and `components/perimeterGlass.css`, all originally scoped `body[data-page="home"]` — every one of those selectors now also carries `body[data-page="journal"]`. A missed selector leaves the DOM perfectly valid while the card renders off-screen (the hero transform applies to a sticky element), which markup tests cannot see; `tests/e2e/specs/journal/journal-hero.spec.js` locks the RENDERED geometry (card in-viewport, centered, rounded, blurred, colon-to-title gap = one square width, feeds open, about copy reveals) — run with `npm run test:e2e` (manual, needs the GSCJ pilot in the registry; it skips otherwise).

The SPA grand tour predates the `journal` structure and does not cover it; `tests/e2e/specs/journal/journal-spa-navigation.spec.js` covers the journal's transitions instead: fresh load → feed card click into the reader (SPA-sentinel-verified, no reload), browser BACK into `/j/{slug}` (the popstate → journal rebuild), forward to the reader again, journal → user page (user button → My Library) → back → feed buttons still work, and the colon link home. That spec caught two real bugs on first run: `window.isOwner` leaking from the user page across SPA transitions and silently gating the journal feed buttons dead (fix: the journal shelf-branch is isOwner-blind + `initializeJournal` scrubs the global), and `DifferentTemplateTransition` pushing the URL only AFTER page init — on a cold cache that left seconds where the new page rendered under the old URL and Back could exit the site entirely (fix: URL pushes right after the body swap, before init; verified against the full grand tour). Known-by-architecture: hero-state links navigate NATIVELY (the SPA link interceptor is bound by lazyLoaderFactory, which exists only after a feed loads) — true on home too, so the colon-to-home step asserts a healthy landing, not an SPA transition. The e2e helpers (`getPageStructure`, `EXPECTED_COMPONENTS`) know the `journal` page type.

## Two lanes per work, and choosing between them

A work can carry two system versions at once: the vacuumed PDF (`foundation_source: canonical_pdf_vacuum`, `conversion_method: pdf_ocr_auto_raw`) and the publisher HTML (`journal_html` / `paste_engine_html`). They are sibling `library` rows on one canonical, each with its own book id and `resources/markdown/{book}/` — the same shape the ar5iv lane has used since it existed, so nothing in the versions model changes. `HtmlLaneCreator` mints and imports the HTML one; it deliberately bypasses `AutoVersionCreator`, which is hard-wired to the PDF foundation and short-circuits at `assigned_existing` the moment any lane has content.

Exactly one lane is **the version**: `canonical_source.auto_version_book` names it, only it is `listed`, and it's what `/j/{slug}`, the shelf and readers resolve to. The other stays imported but unlisted for comparison. Left alone the winner is whichever lane was created FIRST (`AutoVersionResolver` orders by `created_at`) — arbitrary and invisible, which is why `JournalVersionPromoter` exists. Promotion moves the pointer, flips the listing, and **swaps shelf membership**: `HarvestShelf::syncJournalShelfMembership` is additive, so without that last step the journal's feeds keep serving the lane you just demoted.

Import HTML with `journal:harvest <slug> --lane=html|both` (free — only PDF runs OCR), compare at `/maintainer/journal-import/{slug}`, promote with the ★ button or `journal:promote-version <book>`. `--force-html` re-converts lanes that already have content — the path a publisher-processor fix travels to reach already-imported articles — and re-promotes afterwards, because `persistArticle` rewrites the row with `listed = false` and would otherwise pull the promoted lane out of the journal's feeds.

The reader in the left pane is the REAL reader, framed. Session history is joint across a browsing context, so its normal container-close (`history.back()`, consuming the entry the open pushed) steps whatever entry is last in the WHOLE context — which here is another frame's navigation. Live symptom: closing a citation blanked the reader pane (`about:blank`), or the source pane's PDF, or navigated the console itself ("the whole page gets cooked"). `resources/js/utilities/embeddedReader.ts` gates every container history write on "am I framed": embedded, the container closes in place and records state with `replaceState` only — no pushState on open, no back() on close, so the host's history is never touched. At top level every guard is a no-op, so reader behaviour is unchanged (open still pushes `?cs=1`, Back still unwinds a level). GOTCHA if you are ever tempted to stop the frames adding joint-history entries by navigating them with `location.replace()` instead of `.src`: don't. A replace() issued from the frame's own `about:blank` document is treated as a third-party initiator by WebKit, so the `SameSite=Lax` session cookie is not sent and both panes come back `{"message":"Unauthenticated."}` — measured, `.src` keeps the session and `location.replace()` loses it on the identical URL. The extra history entries are the lesser evil; recreating the iframe ELEMENT per selection is the route that would avoid both.

The console acts as well as compares. Per lane: **↻ reconvert** (re-run the converter over the page already on disk — no network, no cost, input held constant so the only variable is your processor fix), **⇩ re-fetch** (go back to the publisher, for when what we stored isn't the article), and the two bundles **⤓ conversion** / **⤓ harvest** — the same converter-vs-acquisition fork, which is why neither is a default. An article with no lanes offers **PDF / HTML / both**. All of it queues a `JournalImportActionJob` on `citation-pipeline` against a `journal_import_runs` row the page polls (these actions fetch, OCR and cost money, so none runs in the request); the poll carries a 30-minute stale-run watchdog, and a second run on the same target joins the first rather than interleaving node writes with it. The PDF lane's reconvert is deliberately the shared `/maintainer/conversion` one — one reconvert implementation, not two — and re-acquiring a PDF stays a retract-and-re-harvest.

The source pane renders in the operator's theme: the fetched page is same-origin, so `utilities/sourceFrameTheme.ts` injects a stylesheet built from the live theme custom properties (read off `<body>`, where the `theme-*` class lives — off `documentElement` you get the dark defaults and every theme looks dark). PDFs are excluded by ARTIFACT, not by inspecting the document — WebKit gives its PDF viewer a real `body`, so a body check reports a PDF as skinnable — and fall back to a light canvas the viewer overpaints. Shared with `/maintainer/conversion`; `tests/javascript/utilities/sourceFrameTheme.test.js` locks the artifact rule.

Each lane also carries the conversion page's detail strip — book id (click to copy), `open ↗`, and a **note** that is stored on the book's open flags and rides the case bundle into dev. Noting a lane nobody has flagged opens a `manual` flag to hold it: you spotting the bad conversion IS the report, and a note with nowhere to live never reaches the bundle. **✓ fixed / ✕ dismiss** close the case on the same page, via a journal-import-specific endpoint rather than the shared conversion resolve — that one lists whatever it approves (approval is the listing gate when a flagged book is the only version of its work), which on a losing lane would publish a second version of one article; here listing follows only for the already-promoted lane. The bundle manifest gained `origin` (which console exported it), a `lane` block (foundation_source, conversion_method, promoted-or-not, and every sibling lane with the same facts) and a `journal` block (slug, name, publisher, ISSN-L, console URL) — because for a harvest case off a journal, WHICH lane broke and whether the sibling is fine is the diagnosis, and `canonical_source.json` alone leaves the importing side holding an unresolvable `journal_source_id`. The `journal_sources` row travels in `db/` and imports insert-if-absent, so the pulled case opens in a local journal-import console.

GOTCHA for any future re-import path: they all end in `persistArticle`, which rewrites the row with `listed = false`. On the promoted lane that silently drops the article out of `/j` and the shelf, so the job and `--force-html` both re-promote afterwards (found live, locked by `JournalLaneTest`).

Two gotchas the GSCJ pilot surfaced, both invisible to markup-level tests. **Publisher front matter can live OUTSIDE the article container**: on Bristol UP the title, authors, affiliation, abstract and keywords sit in a metadata card ABOVE `#articleBody`, so scoping to the body (the right move for the furniture) silently dropped all of them and the book opened cold on "Key messages" — `BristolUPProcessor::buildArticleHeader` rebuilds them, taking the abstract once because the platform emits the block twice as responsive duplicates. **A percentage-height pane needs a definite height all the way to the root**: `body.ji-detail html` is a descendant selector that can never match (the root element is not inside `<body>`), so `<html>` never got its height, `.ji-columns { height: calc(100% - 45px) }` resolved to `auto`, and the three panes grew to the full 107-article list (~8300px). The reader and the HTML source pane still looked right — they flow from the top — but Safari's PDF viewer fits its page to the frame and centres it, so the visible top of an 8340px-tall frame was pure grey backdrop, which reads exactly like "the PDF failed to load". The gate is `tests/javascript/architecture/cssStructure.test.js` ("no descendant selector ending in html/:root").
